# make-knowledge-cards

一个把文章拆成 5~8 张知识卡片的 Skill。输入是粘贴的正文或本地 `.md` / `.txt` 文件，输出是可以直接复习的 Markdown 卡片。

每张卡片只讲一个知识点，固定四段：**标题、核心知识、简明解释、例子或自测问题**。它不做摘要，也不追求覆盖全文——只挑"删掉之后读者会真的少学到东西"的部分。

---

## 1. 它解决什么问题

摘要把文章压成一段话，读完感觉懂了，一周后什么也想不起来。笔记软件里的划线和高亮也一样：保存了原文，但没有变成你能调用的东西。

知识卡片走的是另一条路：每张卡必须能单独拿出来，脱离原文读懂，并且带一个能检验自己是否真懂的钩子——要么是原文的例子，要么是一道必须理解才能答对的问题。

具体要解决三件事：

| 问题 | 这个 Skill 的做法 |
|---|---|
| 分不清什么重要，容易把铺垫和金句当成干货 | 给出「保留判据 + 丢弃清单」，按机制、方法、阈值、因果、误区、前提代价筛选 |
| 一段话里塞了三个观点，复习时抓不住 | 一张卡只承载一个判断，标题写不出单句判断就拆 |
| 总结时忍不住补充原文没有的东西 | 8 条防编造红线，数字、因果、专名一律回溯原文 |

---

## 2. 主要功能

全部功能由 `SKILL.md` 里的规则实现，**不含任何脚本**，不联网、不调用外部 API。

| 功能 | 具体行为 |
|---|---|
| **知识点筛选** | 保留机制、可操作方法、阈值、因果结论、定义分类、反直觉纠错、使用前提与代价；丢弃背景铺垫、轶事、重复强调、金句、广告、无信息量的过渡句 |
| **合并去重** | 同机制多段出现合并；上位概念吃掉下位；边界条件并入相关卡片，不单独成卡 |
| **数量自适应** | 默认 5~8 张；短文本（不足 300 字）2~4 张；真实知识点不足时按实际数量交付，**不凑数** |
| **超量取舍** | 候选超过 8 条时，按可迁移性、解释力、不可替代性、具体性各打 1~3 分取前 8 |
| **四要素模板** | 标题（≤20 字、承载具体判断）+ 核心知识（完整陈述句）+ 简明解释（2~4 句，术语就地解释）+ 例子或自测（标注来源类型） |
| **防编造** | 8 条红线：数字与专名可回溯、不做推算换算、不补因果动机、不加外部知识、不弱化限定、不代作者立论、不臆测细节、不为凑数拆卡 |
| **语言跟随用户** | 中文提问就出中文卡片，即使原文是英文；专名保留原文并括注 |
| **覆盖说明** | 少于 5 张或截断到 8 张时，末尾用一行说明取舍，让缺口可见 |
| **Markdown 输出** | 卡片间 `---` 分隔，可直接粘进 Obsidian、Notion；用户指定路径时另存为 `.md` |

**不是它的功能**：网页抓取、PDF / 图片 / Office 解析、Anki 或 CSV 导出、图形界面。见第 6 节。

## 3. 安装方法

### 前置要求

- 一个能加载 `SKILL.md` 的技能运行环境（本仓库在 WorkBuddy 的技能目录约定下开发与测试）
- 不需要 Python、不需要安装依赖、不需要 API key
- 不需要联网

### 目录结构

```
make-knowledge-cards/
├── SKILL.md            # 技能主体：流程、筛选标准、卡片模板、防编造红线、自检清单
└── agents/
    └── openai.yaml     # 展示名、简介、默认提示词、允许隐式调用
```

### 安装

把 `skills/make-knowledge-cards` 整个目录复制到技能目录：

```bash
# 个人级：所有项目可用
cp -r skills/make-knowledge-cards ~/.workbuddy/skills/

# 项目级：仅在当前仓库生效
mkdir -p .workbuddy/skills
cp -r skills/make-knowledge-cards .workbuddy/skills/
```

### 验证安装

```bash
ls ~/.workbuddy/skills/make-knowledge-cards/
# 应看到 SKILL.md 和 agents/
```

然后在会话里说一句「把这段文字做成知识卡片」，能触发即安装成功。

### 卸载

```bash
rm -rf ~/.workbuddy/skills/make-knowledge-cards
```

### 没有技能环境时

`SKILL.md` 本身就是一份完整的操作手册。把它的正文作为系统提示交给任意模型，同样能得到符合规范的卡片。`agents/openai.yaml` 只用于宿主界面展示，此场景可以忽略。

## 4. 使用方法

### 输入方式

| 方式 | 说法示例 |
|---|---|
| 粘贴正文 | 「把这篇文章做成知识卡片：<正文>」 |
| 指定文件 | 「用 make-knowledge-cards 处理 `./notes/城市热岛.md`」 |

支持 `.md`、`.markdown`、`.txt`。**一次处理一篇**；多篇请分别发起，卡片不会混在一起。

### 触发词

「知识卡片」「学习卡片」「拆解文章」「提炼知识点」「做成卡片」，也认 `knowledge cards`、`study cards`、`distill this article`。

不一定要点名技能。像「这篇文章有哪些值得记住的点」这类请求，也可能被识别为同一意图（`agents/openai.yaml` 里开启了 `allow_implicit_invocation`）。

### 常用追问

- **换掉某张卡**：「第 4 张不算知识点，换成关于风险的」——按你的判断重排，并说明取舍标准要不要跟着改
- **存成文件**：「存到 `~/notes/知识卡片/`」——默认只输出在对话里，明确要求才落盘；未指定文件名时存为 `<原文件名>-知识卡片.md`
- **换语言**：输出语言默认跟你说话的语言一致；要英文卡片就说「用英文输出」

### 输出长什么样

固定结构，没有导读、没有总结陈词、没有评分：

```markdown
## 《标题》知识卡片（共 N 张）

> 来源：用户粘贴 / 文件路径

### 卡片 1｜<一句话判断>

**核心知识**：……
**简明解释**：……
**例子 / 自测**：……

---
```

末尾在需要时附一行 `> 覆盖说明：……`。

## 5. 输入输出示例

### 示例 A：粘贴短文（知识点不足 5 个）

**输入**：

> 睡眠研究里常提到"睡眠债"，但补觉并不能真正还债。连续一周每晚少睡 1 小时，认知测试成绩下降的程度，相当于整夜不睡 24 小时。周末睡 10 小时只能让主观困倦感减轻，注意力的客观指标仍低于基线。原因是深度睡眠的分配集中在前半夜，熬夜直接砍掉的正是这一段，而补觉多出来的是浅睡和快速眼动睡眠。

**输出**：

````markdown
## 《睡眠债》知识卡片（共 3 张）

> 来源：用户粘贴

### 卡片 1｜补觉不能偿还睡眠债

**核心知识**：睡眠债无法靠事后补觉抵消，因为补觉补不回熬夜砍掉的深度睡眠。

**简明解释**：深度睡眠集中在前半夜，熬夜时最先损失的正是这一段。周末延长睡眠多出来的是浅睡和快速眼动睡眠，结构上不等价，所以欠下的部分补不回来。

**例子 / 自测**：原文例——周末睡 10 小时，只让主观困倦感减轻，注意力客观指标仍低于基线。

---

### 卡片 2｜连续少睡 1 小时的代价接近整夜不睡

**核心知识**：连续一周每晚少睡 1 小时，认知成绩下降幅度相当于整夜不睡 24 小时。

**简明解释**：小额亏损会累积。单晚少睡 1 小时几乎无感，但连续七天叠加后，认知损伤的量级与通宵一次相当，主观感受却远没有通宵那么糟。

**例子 / 自测**：自测——为什么单晚少睡 1 小时很难被察觉，连续一周却损失明显？

---

### 卡片 3｜困倦感减轻不等于认知恢复

**核心知识**：主观困倦感与注意力的客观指标会背离，补觉后感觉变好不代表认知功能回位。

**简明解释**：原文用周末补觉的现象说明这一点：困倦感明显减轻，注意力指标仍在基线以下。两者测的不是同一件事，所以"白天不困"不能用来判断睡眠债是否还清。

**例子 / 自测**：自测——一个人说"我睡够了，不困"，还需要什么证据才能认定睡眠充足？

> 覆盖说明：原文片段只含 3 个可独立成立的知识点，其余为机制铺垫，未凑数。
````

这次输出的三个取舍：原文没有研究名称、年份、样本量，卡片里一律不出现；"8 小时"原文没说，所以不写；第二、三张卡没有重复第一张的机制。

### 示例 B：指定文件（长文，截断到 8 张）

**输入**：

```
用 make-knowledge-cards 处理 ./notes/How to Do Great Work.md
```

原文约 1.3 万词，候选知识点 30 余条。**输出节选**（实际 8 张）：

````markdown
## 《How to Do Great Work》知识卡片（共 8 张）

> 来源：文件 ./notes/How to Do Great Work.md

### 卡片 1｜选题只需满足天分与兴趣

**核心知识**：选工作只需满足"有天分"和"深度兴趣"两个条件，第三个条件"有没有做大事的空间"不必纠结。

**简明解释**：原文认为第三条在实践中不用太担心，有雄心的人在这方面反而过于保守——他们不是高估了空间，而是低估了。所以真正要解决的只有一件事：找到自己既擅长又极度感兴趣的领域。

**例子 / 自测**：自测——为什么原文说"这件事够不够重要"不该成为选题时的主要顾虑？

---

### 卡片 2｜选题靠走到前沿，不靠想

**核心知识**：不知道该做什么时先猜一个开始做，因为知识边界的缝隙只有走到前沿才看得见。

**简明解释**：知识像分形一样展开，远看边缘平滑，凑近才发现满是缺口。所以路径是四步：选一个领域、学到能触及前沿、注意到缺口、挑有希望的钻进去。选题不是一次决策，而是这个循环的产物。

**例子 / 自测**：自测——为什么"先想清楚要做什么再开始"在这套方法里行不通？

---

（卡片 3~8 略）

> **覆盖说明**：原文约一万三千词，候选 30 余条，按可迁移性 / 解释力 / 不可替代性 / 具体性打分取前 8。舍弃内容包括：诚实与做作、风格、教育系统的被动性、同事与人才聚集、士气与观众、风险与年龄优势、连续版本与计划、模仿与借用、"问题比答案更重要"。
````

长文只按主线取点，不保证覆盖全文。这是有意的取舍，覆盖说明里会写清丢了什么。

## 6. 边界

| 支持 | 不支持 |
|---|---|
| 粘贴的正文 | 网页抓取 |
| `.md` / `.markdown` / `.txt` | PDF、图片、Office 文档 |
| 中文、英文原文（按用户语言输出） | Anki / CSV / 思维导图导出 |
| Markdown 卡片 | 图形界面或独立应用 |
| 一次一篇 | 多篇合并成一组卡片 |

需要网页或 PDF 时，先把正文存成 `.md` 或 `.txt` 再交给它。

---

## 7. 已知取舍

- **超长文不保证覆盖全文**。5~8 张是设计上限，长文只能覆盖主线。要全量请分段处理。
- **信息密度决定上限**。观点类文章若通篇只有判断没有机制，能提取的知识点会明显偏少，这是原文的问题，不是过滤过严。
- **质量取决于执行模型**。「保留判据 + 丢弃清单 + 防编造红线 + 自检清单」四道闸能压住大部分偏差，但不能消除误判。规则管得住"不编造"，管不住"选得不够好"。
- **没有脚本兜底**。不做 OCR、不做格式转换，也不做后处理校验。

## 8. 校验与实测

技能结构用官方 `skill-creator` 的 `quick_validate.py` 校验通过。该脚本来自 skill-creator，不在本仓库内，需先拿到脚本再执行：

```bash
# 在 skill-creator/scripts/ 目录下
python quick_validate.py <本仓库路径>/skills/make-knowledge-cards
# Skill is valid!
```

实测覆盖五类文本，并据此改过规则：

| 类型 | 样本 | 触发的问题 |
|---|---|---|
| 原理科普 | 城市热岛成因（含数字与机制） | 边界条件易被单独拆卡，改为并入相关卡 |
| 操作教程 | Power Query 合并 12 个月销售表 | 标题退化成"第一步/第二步"；自测题附答案自我泄底 |
| 观点评论 | 降本增效（全篇无数字） | 结尾金句差点成卡，靠丢弃清单拦下 |
| 百字短讯 | 地铁延长运营（约 110 字） | 事后把"再延 30 分钟"算成 23:30；凭空补"为了控制成本" |
| 英文长文 | Paul Graham《How to Do Great Work》，约 1.3 万词 | 语言策略按原文输出，中文用户拿到英文卡 |

由此沉淀的规则：禁止任何推算换算、禁止补原文没有的因果、自测题不附答案且题型轮换、"标题含和/与即拆卡"改为判断能否一句话说完、按用户语言输出而非跟随原文。
