# 知识卡片生成

把一篇完整文章压缩成 5~8 张可独立阅读、可复习的知识卡片。每张卡片只承载一个知识点，所有内容必须能在原文找到依据。

## 适用范围

**支持**：用户直接粘贴的文本；本地 `.md` / `.markdown` / `.txt` 文件路径。

一次处理一篇。多个文件请分别发起，不要合并成一组卡片——不同来源的主线和知识点会互相干扰。

**不支持**（遇到时直接说明，并给出替代路径）：
- 网页抓取 —— 请用户把正文粘贴进来，或另存为 .md/.txt
- PDF / 图片 / Office 文档 —— 请用户先转成纯文本
- Anki、CSV、思维导图等导出格式 —— 只交付 Markdown 文本
- 图形界面或独立应用 —— 只输出 Markdown

不要因为用户要求"顺便抓个网页"就临时扩展能力范围。

## 执行流程

按顺序完成七步，不要跳步直接写卡片。

### 第 1 步：取得全文

- 粘贴文本：直接使用。
- 文件路径：用 Read 工具读取全文。超过 2000 行时按 offset 分段读完，不要只读开头就动笔。
- 文本残缺（明显被截断、只有摘要、大量乱码）：先说明缺什么，再问是否继续。残缺到无法判断主线时，停在这里。
- 用户粘贴的是自己的碎片笔记、主线不明时，按主题分组各出一组卡片，不要硬编一条主线。

### 第 2 步：通读并标出主线

读完再动手。用一句话回答：这篇文章想让读者改变什么认知或行动？

多主题长文中，锁定主线后，偏离主线的枝节即使有趣也降级处理。原文本身就是清单或手册（无单一主线）时，跳过此判断。

### 第 3 步：提取候选知识点

逐段扫描，只捞取符合「重要知识」判据的内容，形成 10~20 条候选要点。长文（超过五千字）放宽到 30 条以上也正常，多记不亏。此时不写卡片，只记要点和原文位置。

### 第 4 步：合并去重

按下面的去重规则收敛候选，通常能砍掉三到五成。

### 第 5 步：排序并截断到 5~8 张

候选多于 8 条时按优先级打分取舍；少于 5 条时**不补**，见「信息不足时」。

### 第 6 步：写卡片

严格套用卡片模板，一次只写一个知识点。

排列顺序按认知路径，不按原文段落顺序：是什么 → 为什么 / 怎么起作用 → 怎么做 → 什么条件下不成立。原文结构本身就是这条路径时可以照搬。

### 第 7 步：自检后输出

过一遍末尾的自检清单，不合格就地重写，不要把问题留给用户。

## 什么算「真正重要的知识」

**保留**（命中任意一条即可）：
- 机制或原理：说清了"为什么会这样"
- 可操作的方法、步骤、判据
- 明确的阈值、数量、条件边界
- 因果关系或结论性判断
- 定义、分类、区分标准
- 反直觉的纠错点、常见误区
- 使用前提与代价

**丢弃**：
- 背景铺垫、行业综述、客套开场
- 作者个人经历与轶事（除非它承载了可迁移的结论）
- 同一观点的反复强调
- 情绪渲染、修辞、金句
- 引流、课程广告、公众号尾巴
- 无信息量的过渡句
- "要重视""要坚持""要拥抱变化"这类没有落地内容的号召

判断标准一句话：**删掉它，读者会不会真的少学到东西？** 不会，就删。

## 合并去重规则

- 同一机制在多段重复出现：合并成一张，解释里保留最完整的那个表述。
- 上位概念包含下位概念：保留上位，下位降级为例证写进解释。
- 同一条因果链上的环节：能独立使用就分开，只是前后铺垫就合并为一张"机制卡"。
- 反例、例外、边界条件：不单独成卡，附在相关卡片解释的末尾。
- 措辞不同但指向同一结论：视为重复，保留信息量最大的版本。

## 候选超过 8 条时的取舍

按四项各打 1~3 分，取总分最高的 8 条：

| 维度 | 高分特征 |
|---|---|
| 可迁移性 | 能用到这篇文章之外的场景 |
| 解释力 | 是机制或因果，而非现象罗列 |
| 不可替代性 | 删掉后文章主线断裂 |
| 具体性 | 有数字、条件、步骤，而非泛泛而谈 |

得分相同则优先保留带具体数值、阈值或步骤的那条。

## 卡片模板

每张卡片固定四段（标题 + 三个字段），中文原文用下列字段名；非中文原文按「输出格式」里的规则翻译字段名，结构不变。

```markdown
### 卡片 1｜<标题>

**核心知识**：<一句话，20~50 字，脱离原文也能读懂>

**简明解释**：<2~4 句，讲清是什么 / 为什么 / 怎么用，术语就地解释>

**例子 / 自测**：<原文中的例子或数据（标注"原文例"）；原文没有例子时，写一道必须理解本卡才能答对的自测题（标注"自测"）>
```

### 标题

- 写明具体概念或结论，不用"关于 XX""第一点"这类空标题。
- 教程类文章不写"第一步""第二步"，改写成这一步防住了什么错，例如「默认合并按钮会猜错表头」。
- 判断是否该拆卡：尝试用一句话说完这张卡的判断。说不完，或者一句话里出现两个互不依赖的判断，就拆。标题里有"和""与"只是提示，成对概念（如维持性成本与投入性成本）不必拆。
- 控制在一行内，不超过 20 字。

### 核心知识

- 必须是完整陈述句，有主语有判断，不是名词短语。
- 一句话能独立成立，不依赖上文代词。
- 反例：「时间管理很重要」——空话。正例：「把任务按 2 分钟内能否完成分流，可减少待办列表的堆积」。

### 简明解释

- 2~4 句，总长 60~150 字。
- 不复述原文长句，用大白话重写；原文术语首次出现时用一句话解释。
- 只解释这一张卡片的知识点，不夹带其他卡片的内容。
- 原文没讲清的部分写"原文未展开"，不要自行补全。

### 例子 / 自测

- **优先用原文自带的例子、数据、场景**，标注「原文例」。数字与单位照抄，不四舍五入、不换算。原文里的分类、清单、阈值同样可以当例子用，不必是故事性案例。
- 原文没有例子时，写一道「自测」题，要求：不能是是非题；答案必须能在本卡内找到；答对需要理解而非背诵。
- 自测题**不附答案**，也不要写成"(答案：...)"。答案留在卡里，让读者自己找。
- 连续几道自测题要换题型：判断情形题（给一个场景问结果）、对比题（两组条件差异）、归因题（为什么）。全篇清一色"为什么"会读成考卷。
- 允许用生活化类比帮助理解，但必须标注「类比，非原文」，且类比不得引入任何新的事实主张（不出现新的人名、机构、数据、时间）。

## 防编造红线

以下任何一条触发，卡片作废重写：

1. **数字、专名、引文**必须能在原文找到原句。找不到就不写。
2. **不做任何推算**。原文说"周五周六再延后 30 分钟"，就只写这一句，不要自己加起来写成 23:30；不做同比、占比、总量、汇率、单位换算。原文没给出的数字，一个都不出现。
3. **不补因果和动机**。原文只陈述"间隔拉长为 15 分钟"，就不能写"为了控制成本"。解释里禁止出现原文没有的"因为""为了""目的是"；机制不明就写"原文未说明原因"。
4. **不补充外部知识**。即使你比原文知道得更多（更新的研究、更好的方法），也不加进去。
5. **不弱化限定**。原文只说相关，就不能写成"导致"；原文说"可能"，就不能写成"一定"。
6. **不代作者立论**。不写"作者认为"后面接原文没有的观点。
7. **不臆测细节**。人名、机构、年份、地点、样本量，原文没有就留空或写"原文未说明"。
8. **不为凑数而拆卡**。把一个知识点切成两张，比少写一张更糟。

## 信息不足时

真实知识点只有 3~4 个时：

- 就输出 3~4 张，**不要**靠拆卡、注水、加常识凑到 5 张。
- 原文不足 300 字（短讯、通稿、片段）时，2~4 张是正常结果，直接按实际数量交付。
- 在末尾加一行覆盖说明，讲清为什么少：

```markdown
> 覆盖说明：原文为短讯，仅含 3 个可独立成立的知识点，其余为背景交代与引用，未凑数。
```

候选超过 8 条被截断时，也补一句说明舍弃了什么类型的内容。

## 输出格式

```markdown
## 《<原文标题或文件名>》知识卡片（共 N 张）

> 来源：<用户粘贴 / 文件路径>

### 卡片 1｜...

---

### 卡片 2｜...
```

- 语言跟随用户：用户用中文提问就出中文卡片，即使原文是英文；用户点名指定语言（"用英文输出""保持原文语言"）时按其指定。专名与术语保留原文，首次出现时括注中文。
- 用非中文提问或用户指定非中文输出时，字段名一并译为对应语言（Core idea / Explanation / Example or self-check），结构不变，不要中英混排。
- 卡片之间用 `---` 分隔，方便粘贴进 Obsidian、Notion。
- 只输出卡片本身。不要附导读、逐段摘要、评分、思考过程或"希望对你有帮助"。
- 用户明确要求存成文件时，写到用户指定路径（未指定则存为 `<原文件名>-知识卡片.md`），并在回复里给出路径。

## 自检清单

输出前逐条确认，任一不合格就重写对应卡片：

- [ ] 卡片数在 5~8 张之间；短文本 2~4 张亦可；不足 5 张时已附覆盖说明
- [ ] 每张卡只有一个知识点，能用一句话说完这张卡的判断
- [ ] 核心知识是完整陈述句，脱离上下文可读
- [ ] 简明解释没有照抄原文长句
- [ ] 每个数字、专名、引文都能在原文定位，且没有经过任何推算或换算
- [ ] 解释里没有原文之外的"因为/为了/目的是"
- [ ] 没有出现原文之外的事实、评价
- [ ] 自测题不附答案，题型不重复
- [ ] 例子标注了来源类型（原文例 / 自测 / 类比，非原文）
- [ ] 卡片之间无重复，边界条件已并入相关卡片
- [ ] 卡片顺序按认知路径排列，不是段落顺序的复刻
- [ ] 全文没有铺垫、总结陈词、广告残留

## 示例

输入片段（节选）：

> 睡眠研究里常提到"睡眠债"，但补觉并不能真正还债。连续一周每晚少睡 1 小时，认知测试成绩下降的程度，相当于整夜不睡 24 小时。周末睡 10 小时只能让主观困倦感减轻，注意力的客观指标仍低于基线。原因是深度睡眠的分配集中在前半夜，熬夜直接砍掉的正是这一段，而补觉多出来的是浅睡和快速眼动睡眠。

输出：

```markdown
## 《睡眠债》知识卡片（共 3 张）

> 来源：用户粘贴

### 卡片 1｜补觉不能偿还睡眠债

**核心知识**：睡眠债无法靠事后补觉抵消，因为补觉补不回熬夜砍掉的深度睡眠。

**简明解释**：深度睡眠集中在前半夜，熬夜时最先损失的正是这一段。周末延长睡眠多出来的是浅睡和快速眼动睡眠，结构上不等价，所以欠下的部分补不回来。

**例子 / 自测**：原文例——周末睡 10 小时，只让主观困倦感减轻，注意力客观指标仍低于基线。

---

### 卡片 2｜连续少睡 1 小时的代价接近整夜不睡

**核心知识**：连续一周每晚少睡 1 小时，认知成绩下降幅度相当于整夜不睡 24 小时。

**简明解释**：小额亏损会累积。单晚少睡 1 小时几乎无感，但连续七天叠加后，认知损伤的量级与通宵一次相当，主观感受却远没有通宵那么糟。

**例子 / 自测**：自测——为什么单晚少睡 1 小时很难被察觉，连续一周却损失明显？

---

### 卡片 3｜困倦感减轻不等于认知恢复

**核心知识**：主观困倦感与注意力的客观指标会背离，补觉后感觉变好不代表认知功能回位。

**简明解释**：原文用周末补觉的现象说明这一点：困倦感明显减轻，注意力指标仍在基线以下。两者测的不是同一件事，所以"白天不困"不能用来判断睡眠债是否还清。

**例子 / 自测**：自测——一个人说"我睡够了，不困"，还需要什么证据才能认定睡眠充足？

> 覆盖说明：原文片段只含 3 个可独立成立的知识点，其余为机制铺垫，未凑数。
```

注意示例里的三个取舍：原文只提到"睡眠研究"，没有研究名称、样本量、年份，卡片里一律不出现；"8 小时"原文没说，所以不写；第二、三张卡没有重复"深度睡眠集中在前半夜"这个机制，那是第一张卡的内容。
